# Feature 9 — The Real Frontend (HTML / CSS / JS)

> **Milestone:** the browser finally *displays* what our API returns. We build the landing search + a dynamic portfolio page in **vanilla JS** — so that when React arrives (F10), the pain it solves is obvious.

---

## Step 1 · What are we building today

1. A **landing page** at `/` (served by FastAPI `HTMLResponse`): a search box + a hero + the global "total generated" counter.
2. A **portfolio page**: type a username → we `fetch` `/users/{username}/portfolio`, render identity, stats, and a language donut — all in the browser.
3. A **theme toggle** (dark/light) persisted to `localStorage`.

```
   ┌─────────────────────────────┐
   │  [⚙ dark]  GitHub Portfolio │
   │  ┌───────────────────────┐   │
   │  │ search: [torvalds] Go  │   │
   │  └───────────────────────┘   │
   │  Name · followers · repos     │
   │  [stats grid] [language bars] │
   └─────────────────────────────┘
```

---

## Step 2 · Why do we need this feature

We have a real API, but nobody can *use* it. "The frontend" isn't optional polish — it's how the project becomes an app instead of a curl-able API. And because a `fetch` call + a render is the *entire* pattern, this feature is where you finally wire the two halves (browser ⇄ server) you've been studying apart.

We start **vanilla** deliberately: there's no framework hiding the DOM/HTTP work. By F10 you'll *feel* that the manual "state → re-render" chore is exactly what React automates.

---

## Step 3 · What new technologies are required

Only the browser's built-ins:

| Technology | Why this feature needs it |
|-----------|---------------------------|
| **HTML/CSS** | the structure + theme styling |
| **The DOM + `document` / CSS selectors** | grab elements and fill them |
| **`fetch` + `async/await`** | call our FastAPI endpoints, parse JSON |
| **`localStorage`** | persist theme, last-searched username |
| (reuse) FastAPI `StaticFiles` for CSS/JS | serve our files |

No React yet. No bundler. No build step. The browser + these APIs.

## Step 4 · Teach only the required concepts

### 4.1 Serving static files from FastAPI

```python
from fastapi.staticfiles import StaticFiles
app.mount("/static", StaticFiles(directory="static"), name="static")
```
Now `/static/css/index.css` and `/static/js/main.js` are served. `app.mount` (not `@app.get`) serves a whole directory.

### 4.2 `fetch` (the browser's HTTP client — symmetric to httpx)

```js
const res = await fetch(`/api/v1/users/${encodeURIComponent(username)}/portfolio`);
if (!res.ok) {
  const body = await res.json().catch(() => null);
  throw new Error(body?.error?.message ?? `HTTP ${res.status}`);
}
const data = await res.json();
```

- `encodeURIComponent` — don't let a username break the URL.
- **Always `res.ok`** (status 2xx) check before `.json()`.
- This is the exact mirror of our server's `httpx` usage — both make HTTP. The realization "our JS is a client, like our Python client was" clicks the whole system together.

### 4.3 Building DOM safely (XSS)

API data (bios, repo names) is *untrusted* — it could contain `<script>`. Never inject it via `innerHTML`. Build nodes or set `.textContent`:

```js
const li = document.createElement("li");
li.textContent = repo.name;      // text only; never innerHTML = repo.name
list.appendChild(li);
```

**This is a security lesson that becomes second nature** — anyone who does `innerHTML = userData` is writing XSS.

### 4.4 State + re-render (the pain React will fix)

The naive approach: a `render(data)` function that sets the whole page from a JS object, called whenever data changes.

```js
let state = null;
async function searchUser(username) {
  state = await loadPortfolio(username);   // fetch
  render(state);                           // draw everything from state
}
```

Every change → call `render()`. Fine for one page. When theme + template + data all interact (F10), this manual choreography *hurts* — feel it now.

## Step 5 · Implementation plan

```
static/
├── css/index.css        # all styles (mobile-friendly; theme via CSS vars)
├── js/main.js           # state, fetch, render logic
└── index.html           # landing markup (or generated by FastAPI)
app/
└── routers/web.py       # GET /  → HTMLResponse
```

| File | Why |
|------|-----|
| `static/js/main.js` | the app logic: fetch + render + theme |
| `static/index.html` | a static shell (or a server-rendered `HTMLResponse`) |
| `routers/web.py` | serve `/` (and later redirect `/p/...` to the SPA) |

**Decision:** we serve a static `index.html` from `/static` and have `GET /` return it (via `FileResponse`). The frontend then calls our JSON API. That's a classic "SPA-shell + REST" split.

## Step 6 · Implement gradually

### Piece 1 — a serve index route

```python
# app/routers/web.py
from fastapi.responses import HTMLResponse

@router.get("/", response_class=HTMLResponse)
def index():
    return open("static/index.html").read()
```
(Or mount static + `FileResponse`.) This one fallback is how `/` works again.)

### Piece 2 — the HTML shell + CSS

```html
<!doctype html><html lang="en" data-theme="dark"><head><title>GitHub Portfolio</title>
<link rel="stylesheet" href="/static/css/index.css"></head>
<body>
  <header>
    <h1>GitHub Portfolio</h1>
    <button id="theme">🌙</button>
  </header>
  <form id="search">
    <input name="username" placeholder="github username" autocomplete="off">
    <button>Go</button>
  </form>
  <section id="result" class="hidden">
    <h2 id="name"></h2>
    <div id="stats"></div>
    <div id="langs"></div>
  </section>
  <script type="module" src="/static/js/main.js"></script>
</body></html>
```

```css
:root { --bg:#fff; --fg:#111; --accent:#0969da; }
[data-theme="dark"] { --bg:#0d1117; --fg:#f0f6fc; --accent:#58a6ff; }
body { background: var(--bg); color: var(--fg); ... }
```
The **theme toggle is just swapping `data-theme` on `<html>`** — CSS variables do the rest. (That's the responsive/theme "architecture": variables + attribute.)

### Piece 3 — the JS: fetch + render (vanilla)

```js
// static/js/main.js
import { renderPortfolio, renderLangs } from "./render.js";

const form = document.getElementById("search");
form.addEventListener("submit", async (e) => {
  e.preventDefault();                                  // stop page reload
  const username = form.elements.username.value.trim();
  try {
    const data = await fetchPortfolio(username);
    renderPortfolio(data);                              // fill #name, #stats
    renderLangs(data.top_languages, document.getElementById("langs"));
  } catch (err) { alert(err.message); }
});

// theme toggle
const themeBtn = document.getElementById("theme");
const root = document.documentElement;
themeBtn.addEventListener("click", () => {
  const next = root.dataset.theme === "dark" ? "light" : "dark";
  root.dataset.theme = next;
  localStorage.setItem("theme", next);
});
if (localStorage.getItem("theme")) root.dataset.theme = localStorage.getItem("theme");
```

- `e.preventDefault()` stops the form from reloading the page (the #1 beginner gotcha).
- `localStorage` keeps the theme across sessions.
- `import` + `type=module` => we split JS into modules (separation of concerns continues into the frontend).

### Piece 4 — render functions (the "UI = f(state)" seed)

```js
// static/js/render.js
export function renderPortfolio(data, username) {
  document.getElementById("name").textContent = data.user.name || username;
  const stats = document.getElementById("stats");
  stats.textContent = `${data.total_repos} repos · ${data.total_stars} ★`;
}
export function renderLangs(langs, container) {
  container.innerHTML = "";
  for (const l of langs) {              // textContent for any lang name
    const bar = document.createElement("div");
    bar.style.width = l.percentage + "%";
    bar.setAttribute("aria-label", `${l.name}: ${l.percentage}%`);
    container.appendChild(bar);
  }
}
```
Simple, safe (textContent), and a first taste of "given data, draw a cell."

## Step 7 · Request lifecycle (full frontend round-trip)

```
User types "torvalds" + Enter
  │ browser (JS) fetch → GET /api/v1/users/torvalds/portfolio
  │     (your FastAPI stack: rate limit, cache, GitHub, DB -> JSON)
  ▼
  │ browser: res.ok? → data = await res.json()
  │ renderPortfolio(data) → updates DOM (#name, #stats, #langs)
  │ browser repaints the changed nodes
  ▼
Ust sees "Linus Torvalds · 12 repos · 4,000 ★"
```

**This is the loop you've been tracing** — now the browser half actually does something with the JSON.

## Step 8 · Alternatives

- **Full-JSON server + JS SPA** (we chose) vs **server-side templates (Jinja)** that fill HTML on the server. We chose SPA to teach `fetch`/DOM; Jinja is simpler for static pages and avoids client-state bugs. Trade-off: server HTML = faster first paint, less JS; SPA = richer interactivity.
- **innerHTML vs DOM/textContent** — textContent is safe, innerHTML is convenient but dangerous with API data.
- **No build step (this) vs bundler (Vite) vs React (F10)** — no-build is clearest for learning; a bundler arrives with React.

---

## Step 9 · Refactor as a senior

- **Split JS into modules** (`fetch.js`, `render.js`, `theme.js`) — same "one responsibility per file" discipline as backend.
- **Error UI** with the shape we standardized on (`.error.body` → message). One `showError()` reused.
- **Accessibility**: `<button>` text, `aria-label` on visual-only bars, `lang` attribute. Small effort, big professional point.
- **Network resilience**: `AbortController` timeout on fetch + clear loading/failure states.
